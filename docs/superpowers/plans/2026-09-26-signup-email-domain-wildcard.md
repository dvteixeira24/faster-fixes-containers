# Signup Email Domain Wildcard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Allow `*@domain` entries in the public-signup email whitelist to accept direct addresses at that domain without accepting its subdomains.

**Architecture:** Keep all policy decisions in the existing `canSignUpWithEmail` helper created by the Docker patch. Normalize the candidate and configured entries, retain exact-address lookup, then construct one direct-domain wildcard key from the candidate's complete domain. A repository-level Node test extracts and imports the helper produced by the patch so behavior is verified without modifying the pinned upstream submodule.

**Tech Stack:** TypeScript, Node.js 22 built-in test runner and type stripping, unified diff patches, Docker.

const originalEnabled = process.env.SIGNUP_EMAIL_WHITELIST_ENABLED;

let temporaryDirectory;

  const filePatch = patch.match(
    /\+\+\+ b\/apps\/web\/src\/server\/auth\/signup-email-whitelist\.ts\r?\n([\s\S]*?)(?=\r?\n--- a\/)/,
  );
  assert.ok(filePatch, "signup whitelist helper is present in the patch");

  const source = filePatch[1]
    .split(/\r?\n/)
    .filter((line) => !line.startsWith("@@"))
    .filter((line) => line.startsWith("+") && !line.startsWith("+++"))
    .map((line) => line.slice(1))
    .join("\n");

  await writeFile(modulePath, source);

beforeEach(() => {
  process.env.SIGNUP_EMAIL_WHITELIST_ENABLED = "true";
  process.env.SIGNUP_EMAIL_WHITELIST = "";
});

after(async () => {
  if (originalEnabled === undefined) {
    delete process.env.SIGNUP_EMAIL_WHITELIST_ENABLED;
  } else {
    process.env.SIGNUP_EMAIL_WHITELIST_ENABLED = originalEnabled;
  }
  if (originalWhitelist === undefined) {
    delete process.env.SIGNUP_EMAIL_WHITELIST;
  } else {
    process.env.SIGNUP_EMAIL_WHITELIST = originalWhitelist;
  }
  await rm(temporaryDirectory, { force: true, recursive: true });

test("preserves exact email matching", () => {
  process.env.SIGNUP_EMAIL_WHITELIST = " Admin@Example.com ";

  assert.equal(canSignUpWithEmail("admin@example.com"), true);
  assert.equal(canSignUpWithEmail("other@example.com"), false);

test("accepts direct-domain wildcard entries", () => {

  assert.equal(canSignUpWithEmail("alice@provider.com"), true);
  assert.equal(canSignUpWithEmail("BOB@PROVIDER.COM"), true);

  assert.equal(canSignUpWithEmail("administrator@provider.com"), false);
});

```ts
export function canSignUpWithEmail(email: string): boolean {
  if (!isSignupEmailWhitelistEnabled()) {
    return true;
  }

  const allowedEmails = new Set(
    (process.env.SIGNUP_EMAIL_WHITELIST ?? "")
      .split(",")
      .map((address) => address.trim().toLowerCase())
      .filter(Boolean),
  );
  const normalizedEmail = email.trim().toLowerCase();

  if (allowedEmails.has(normalizedEmail)) {
    return true;
  }

  const separatorIndex = normalizedEmail.lastIndexOf("@");
  if (separatorIndex <= 0 || separatorIndex === normalizedEmail.length - 1) {
    return false;
  }

  const domain = normalizedEmail.slice(separatorIndex + 1);
  return allowedEmails.has(`*@${domain}`);
}
```

Update the new-file hunk count from `+1,24` to `+1,35` so the unified diff remains valid.
